# Генерация структурированного ФОС с валидацией

`generate_fos.py` — самостоятельный следующий этап после RAG.
Он принимает контекст, который создаёт команда `fos_rag.py context`.
Не меняет базу и не вызывает эмбеддинги. Поэтому контекст может быть
получен и с эмбеддингами Cloud.ru: способ индексации для генератора не важен.
Генерация в этой версии выполняется через официальный GigaChat API.
Ключ Cloud.ru `GIGACHAT_API_2` не является ключом этого генератора.

## Запуск

Скопируйте скрипт и requirements в `rag_gigachat/` или `rag/`.

```bash
pip install -r requirements-fos-generation.txt
```

Используется Pydantic 2 и SDK gigachat 0.2.3, проверено на Python 3.12.
Перед реальным запуском в этом же терминале задайте ключ авторизации:

```bash
read -rsp 'Ключ авторизации GigaChat: ' GIGACHAT_CREDENTIALS
export GIGACHAT_CREDENTIALS
export GIGACHAT_SCOPE='GIGACHAT_API_PERS'
```

SDK автоматически получает и обновляет токен. Для B2B/CORP задайте scope
вашего подключения. При необходимости задайте `GIGACHAT_CA_BUNDLE_FILE`
с путём к существующему PEM-файлу доверенных сертификатов. Проверка TLS
включена. `.env` автоматически этим скриптом не загружается.

Сначала получите контекст существующей командой RAG (с нужной моделью
эмбеддингов, если вы изменили её по сравнению с дефолтом):

```bash
python fos_rag.py --db rpd_gigachat.sqlite3 context \
  --curriculum ../parser/parsed_curriculum.json \
  --discipline-code 'Б1.О.05' \
  --query 'Темы, компетенции, задания для зачёта и критерии оценивания' \
  --limit 12 -o physical_culture_context.json
```

Затем создайте ФОС:

```bash
python generate_fos.py generate \
  --context physical_culture_context.json \
  --model GigaChat-2 \
  --min-tasks 3 \
  --max-tokens 6000 \
  -o physical_culture_fos.json
```

Выберите доступный вашему аккаунту идентификатор модели. Максимум
две генерации: первая и одна попытка исправления (`--repairs 1`, дефолт).
Чтобы отключить исправление, задайте `--repairs 0`.
При транспортной ошибке, фильтрации или обрезке ответа генератор завершает
работу с ошибкой; это не повод автоматически исправлять содержание.

## Что проверяется

- Строгая структура: обязательные поля, непустые строки, типы, отсутствие
  лишних полей, положительные целые баллы.
- Точное совпадение кода и названия с учебным планом.
- Разрешённые компетенции и наличие заданий на каждую компетенцию плана.
- Задания для каждой пары формы/семестра аттестации из плана.
- Уникальные ID и отсутствие одинаковых формулировок заданий.
- Наличие ожидаемого ответа и критериев с описанием нулевого/полного балла.
- Совпадение суммы баллов критериев с максимальным баллом задания.
- Известный `ref` и наличие цитаты в соответствующем фрагменте.
- Хотя бы одна цитата из РПД для каждого задания.

`stage=current` обозначает текущий контроль, поля `assessment_kind` и
`semester` должны быть null. `stage=final` обозначает контроль, указанный
в assessments плана; копируются `kind` и `semester`, например `pass`, 1.
Для курсовой работы/проекта также используется соответствующая пара из
assessments. Это техническая группировка заданий данного PoC.

Часы, кредиты, описание компетенций и остальные факты плана сохраняются
в `curriculum_facts` напрямую из входа. Модели не поручается переписывать их.

## Результат

Файл содержит `status`, `model`, `curriculum_facts`, `sources`, `fos`,
`validation`, `attempts` и SHA256 контекста. Источники сохраняют исходные
имена документов и местоположение фрагментов, если они были во входе.

- `requires_teacher_review`: формальные проверки пройдены.
- `validation_failed`: исправление не помогло, черновик не прошёл проверку.

Ошибочный черновик и сырые ответы сохраняются для диагностики; их нельзя
считать прошедшим валидацию результатом. `attempts` содержит все ответы
и замечания, переданные на исправление. При ошибке API файл результата
не создаётся и существующий файл результата не перезаписывается.

Коды завершения: 0 — проверки пройдены, 1 — не пройдены, 2 — ошибка
входных данных, доступа/API или файловой операции.

Повторная проверка после ручного редактирования работает без ключа:

```bash
python generate_fos.py validate physical_culture_fos.json \
  --context physical_culture_context.json --min-tasks 3
```

Можно передать как полный файл результата, так и непосредственно объект FOS.
Схему можно получить без API:

```bash
python generate_fos.py schema > fos_schema.json
```

## Ограничения

Проверка цитаты подтверждает только её наличие в источнике, а не то,
что источник доказывает корректность ответа или действительно соответствует
названной теме. Покрытие компетенций по кодам не доказывает педагогическую
пригодность задания. `min_tasks` — минимальное количество заданий,
а не критерий полноты всей дисциплины. Официальные индикаторы не
извлекаются в отдельную схему этой версией.

Задания и критерии — авторские предложения модели, подлежащие проверке.
Отсутствующие данные и методические требования отображаются как
предупреждения; предупреждения не блокируют формально корректный черновик.
Валидатор не проверяет полноту тем всей РПД: он видит только входной контекст.
Шкалы промежуточных баллов и итогового зачёта/оценки здесь не реализованы.
Выход — JSON; экспорт DOCX следует добавить отдельно.

## Тесты

```bash
python -m unittest -v test_generate_fos.py
```

Тестовые данные синтетические, не относятся к реальному учебному плану.
Проверяются не только успешный результат, но и ошибочные компетенции,
аттестация, цитаты, баллы, дубли, лимит исправлений и офлайн CLI.
Реальные запросы с вашим ключом не выполнялись.

SDK: https://developers.sber.ru/docs/ru/gigachat/guides/using-sdks
